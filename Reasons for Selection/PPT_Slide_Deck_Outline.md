## Slide 2. 문제 제기: 기존 네트워크의 한계 (The Problem)
* **슬라이드 레이아웃:** 3열 비교 카드 (3-Column Problem Cards)
* **슬라이드 제목:** Why Autonomous Network? : 전통적 네트워크 인프라의 한계
* **서브 카피:** "지능화된 공격과 트래픽 폭주 앞에 하드웨어 중심 네트워크는 무력합니다."
* **카드 1: 정적 하드웨어의 종속성**
  * 벤더사 전용 CLI 및 수동 펌웨어 설정 의존
  * 동적으로 변화하는 비정상 트래픽에 실시간 대처 불가
* **카드 2: 수동 대응의 치명적 지연 (Human Bottleneck)**
  * 공격 발생 시 엔지니어가 로그 확인 후 수동 ACL 입력까지 수 분~수십 분 소요
  * 대응 지연 동안 대규모 서비스 다운타임(Downtime) 및 경제적 손실 발생
* **카드 3: 분산 제어의 시야 한계**
  * 스위치/라우터가 독립적으로 동작하여 전체 토폴로지 최적 우회 경로 계산 불가
* **비주얼 요소:** 경고 아이콘, 정체된 네트워크 패킷 및 관리자 당황 일러스트
* **발표자 노트:**
  > "전통적인 네트워크는 장비별로 수동 설정해야 하며, DDoS 같은 공격이 들어오면 사람이 로그를 보고 방화벽을 칠 때까지 서비스가 중단됩니다. 관리자의 개입 없이 네트워크 스스로 문제를 인지하고 해결하는 자율화가 절실한 이유입니다."

## Slide 4. 핵심 가치 ①: 자율 폐루프의 완결성 (Closed-Loop Defense)
* **슬라이드 레이아웃:** 5단계 수평 프로세스 플로우 (5-Step Horizontal Flowchart)
* **슬라이드 제목:** Core Value 1 : 감시를 넘어 '자가 치유(Self-Healing)'로
* **서브 카피:** "감지부터 차단, 우회, 복구까지 1초 내에 완성되는 완전 폐루프"
* **단계별 구성:**
  1. **[Step 1. 수집]** 주기적 스위치 포트/플로우 통계 폴링 (2-Tier 모니터링)
  2. **[Step 2. 탐지]** 경량 머신러닝(Isolation Forest) 기반 비정상 트래픽 실시간 스코어링
  3. **[Step 3. 격리]** 위조 IP에 속지 않는 단독 인그레스 포트(`in_port`) Drop 규칙 주입
  4. **[Step 4. 우회]** Dijkstra 알고리즘으로 계산된 안전한 대체 경로로 정상 트래픽 동적 전환
  5. **[Step 5. 복구]** 공격 소멸 감지(FSM) 시 기본 최단 경로로 무중단 자동 롤백
* **비주얼 요소:** 화살표로 이어지는 원형 폐루프(Feedback Loop) 그래픽 및 단계별 상태 아이콘
* **발표자 노트:**
  > "핵심은 '완전한 폐루프'입니다. 감지에서 끝나는 것이 아니라, 공격 포트를 격리하고, 피해 링크의 정상 트래픽을 즉시 안전한 경로로 우회시키며, 공격이 끝나면 원래대로 되돌리는 자가 치유 라이프사이클을 완성했습니다."

## Slide 6. 핵심 가치 ③: 실무적 해법 (In-Port Defense against Spoofing)
* **슬라이드 레이아웃:** 좌우 분할 대비 레이아웃 (Split Comparison: Naive vs Our Approach)
* **슬라이드 제목:** Core Value 3 : IP 스푸핑 공격에 대한 현실적이고 날카로운 해법
* **서브 카피:** "무작위 IP 변조 공격에도 스위치와 정상 통신을 완벽히 보호합니다."
* **좌측: 기존의 순진한 접근법 (Naive IP Blocking)**
  * Scapy 등으로 출발지 IP 무작위 변조(Random Spoofing) 공격 주입
  * IP별로 차단 규칙을 생성하다가 스위치 플로우 테이블 폭발 (Flow Table Exhaustion)
  * 결과: 전체 스위치 통신 마비 및 방어 실패
* **우측: 본 시스템의 독창적 해법 (Port-Aware In_port Isolation)**
  * IP가 아닌 패킷이 유입되는 **물리적 진입 포트(`in_port`)를 특정하여 격리**
  * **포트 분류:** 스위치 간 트렁크(Trunk) 포트는 보호, 공격 단말의 액세스(Access) 포트만 타겟팅
  * 결과: 플로우 테이블 낭비 제로, 정상 단말 간 통신 100% 보장
* **비주얼 요소:** 좌측은 X 표시(플로우 테이블 레드 경고), 우측은 체크 표시(정밀 타겟팅 실드 아이콘)
* **발표자 노트:**
  > "실제 공격자는 IP를 초당 수천 개씩 위조합니다. IP를 일일이 막으려 하면 스위치가 먼저 터집니다. 저희는 패킷이 들어오는 '물리적 진입 포트'를 식별하여 차단하고 트렁크 포트를 지켜냄으로써 정상 트래픽을 완벽히 보호하는 실무적 해법을 적용했습니다."

## Slide 7. 시스템 아키텍처 (System Architecture)
* **슬라이드 레이아웃:** 계층형 블록 다이어그램 (4-Tier Architectural Diagram)
* **슬라이드 제목:** System Architecture : 비동기 마이크로서비스 관제 아키텍처
* **서브 카피:** "Ryu 이벤트 루프 블로킹을 방지한 고성능 비동기 분산 파이프라인"
* **계층별 구조:**
  * **[Layer 4: Web Frontend]** React 18 + vis-network (실시간 토폴로지 동적 렌더링) + ApexCharts
  * **[Layer 3: Web Backend]** FastAPI + Uvicorn (Asyncio WebSocket 클라이언트 멀티캐스팅)
  * **[IPC Bus]** Redis 7.2 Pub/Sub (Ryu-AI-FastAPI 간 락 없는 고속 메시지 큐)
  * **[Layer 2: Control Plane]** Ryu Controller (Docker Python 3.8 / OpenFlow 1.3) + 독립 AI 추론 워커 (Python 3.10)
  * **[Layer 1: Data Plane]** Mininet 가상 토폴로지 + Open vSwitch (OVS 2.17) + Scapy 트래픽 발생기
* **비주얼 요소:** 깔끔한 계층 박스 및 상하 데이터 흐름 화살표 (WebSocket, Redis IPC, OpenFlow 1.3)
* **발표자 노트:**
  > "Ryu 컨트롤러 내부에서 AI를 직접 돌리면 스위치 연결이 끊어지는 구조적 한계가 있습니다. 저희는 AI와 웹, 컨트롤러를 독립 프로세스로 격리하고 초고속 Redis Pub/Sub으로 엮어 안정성과 확장성을 모두 잡았습니다."

* **비주얼 요소:** vis-network 토폴로지 UI 목업 화면 (녹색/적색/파란색 경로 대비 강조)
* **발표자 노트:**
  > "네트워크 프로젝트는 터미널 글자만 보여주다 끝나기 쉽습니다. 저희는 웹 대시보드를 통해 공격 유입, 포트 차단, 우회 경로 활성화, 자가 복구까지의 전 과정을 직관적인 애니메이션과 실시간 차트로 시연할 수 있도록 구축했습니다."
