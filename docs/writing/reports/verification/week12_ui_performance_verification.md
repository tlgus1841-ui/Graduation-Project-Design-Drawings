# 12주차 성능 검수서: 관제탑 UI 60fps 유지

| 항목 | 내용 |
|:---|:---|
| 작성 | 김관우 (PM & Tech Writer) |
| 측정일 | 2026.10.07 |
| 대상 | `ui/` 관제탑 (React 18, vis-network 9, ApexCharts 3) |
| 측정 도구 | `ui/scripts/fps-check.mjs` (`npm run perf`) |
| 원본 데이터 | [`data/week12_ui_fps.json`](data/week12_ui_fps.json) |

## 1. 검수 목적

시연 중 공격이 들어오면 관제탑에서 경보 점멸, 지도 색 변경, 차트 갱신이 동시에 일어난다. 이때 화면이 끊기면 시연 품질이 떨어지고 경보가 늦게 보인다. 목표는 **공격·격리·복구 전 과정에서 60fps 유지**다.

## 2. 측정 방법

- 더미 데이터 백엔드와 빌드된 화면을 띄우고, 브라우저 안에서 `requestAnimationFrame` 간격을 80초 동안 기록한다. 80초는 보정 → 정상 → 공격 → 격리 → 복구 확인 한 사이클을 모두 지나는 시간이다.
- 50ms를 넘는 긴 작업(Long Task)을 `PerformanceObserver`로 함께 센다.
- 일반 CPU와 **CPU 4배 감속**(저사양 노트북 가정) 두 조건으로 잰다.

| 지표 | 의미 | 기준 |
|:---|:---|:---|
| 평균 FPS | 초당 화면 갱신 횟수 | ≥ 58 |
| p99 프레임 시간 | 가장 느린 1% 프레임의 시간 | ≤ 16.7ms × 2 |
| 끊김 비율 | 33.3ms(30fps)를 넘긴 프레임 비율 | ≤ 1% |

## 3. 1차 측정에서 발견한 문제

| 조건 | 평균 FPS | p99 | 최대 프레임 | 끊김 | 긴 작업 |
|:---|:---:|:---:|:---:|:---:|:---:|
| 일반 CPU | 58.6 | 33.4ms | 83ms | 1.0% | 25회 (최대 99ms) |
| CPU 4배 감속 | **47.4** | **233ms** | **417ms** | 2.2% | 79회 (최대 413ms) |

2초마다 데이터가 들어올 때마다 화면이 멈칫했다. CPU 프로파일로 원인 두 가지를 찾았다.

1. **같은 순간 6번 다시 그림.** 한 번의 측정 주기에 메시지가 6개 들어온다(스위치별 통계 4개, 상태, 토폴로지). 메시지마다 화면 전체를 다시 그려서 차트도 6번 다시 그렸다.
2. **보이지 않는 라벨 240개.** 차트 마지막 점에 숫자를 붙이려고 모든 점에 라벨을 켜고 빈 문자열을 넣었다. 차트 라이브러리는 빈 라벨까지 매번 만들고 크기를 쟀다(`getBBox`). 4배 감속 조건에서 CPU 시간의 대부분이 여기서 쓰였다.

## 4. 개선 내용

| 개선 | 파일 | 효과 |
|:---|:---|:---|
| 한 프레임에 들어온 메시지를 모아 한 번에 반영 | `hooks/useControlTowerSocket.js`, `lib/towerState.js` (`batch`) | 주기당 다시 그리기 6회 → 1회 |
| 차트 옵션 고정, 무거운 패널은 바뀐 경우에만 다시 그림 | `TrafficCharts.jsx`, `TopologyMap.jsx`, `EventFeed.jsx` (`memo`) | 불필요한 차트·지도 갱신 제거 |
| 점마다 붙이던 차트 라벨 제거 → 차트 위에 최신값 한 줄 | `TrafficCharts.jsx` (`LatestValues`) | 라벨 240개 생성·측정 제거 |

최신값은 차트 위에 "H_legit (S1:1) 47 PPS · H_attacker (S1:2) 3,086 PPS"처럼 이름과 함께 표시해, 색만으로 구분하지 않는 원칙은 그대로 지켰다.

## 5. 개선 후 측정

| 조건 | 평균 FPS | p99 | 최대 프레임 | 끊김 | 긴 작업 |
|:---|:---:|:---:|:---:|:---:|:---:|
| 일반 CPU | **60.0** | **16.8ms** | 50ms | **0%** | 1회 (55ms) |
| CPU 4배 감속 | **56.6** | **16.8ms** | 267ms | **0.9%** | 40회 (최대 278ms) |

- 일반 CPU에서 한 사이클 동안 **60fps를 그대로 유지**했다. 끊긴 프레임은 0개다.
- 4배 감속에서도 평균 47.4 → 56.6fps, p99 233 → 16.8ms로 줄었다. 남은 긴 작업은 2초마다 한 번 있는 차트 다시 그리기다.

**판정: 통과.** 시연 환경(일반 노트북)에서 60fps 유지, 저사양 조건에서도 끊김 1% 미만.

## 6. 측정 조건과 한계

- 측정은 헤드리스 Chromium(가상 디스플레이, GPU 없음)에서 했다. 실제 노트북 브라우저는 GPU 가속이 있어 같거나 더 좋게 나올 가능성이 높다.
- 시연 PC에서 `cd ui && npm run build && npm run perf`로 같은 측정을 다시 할 수 있다.
- 실데이터(live 모드)도 2초 주기·스위치별 메시지 구조가 같아, 이번 개선이 그대로 적용된다.
