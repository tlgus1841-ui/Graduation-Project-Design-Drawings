# 관제탑 사용자 매뉴얼 (Operator Manual)

> Self-Defending SDN Tower 관제탑을 처음 쓰는 운영자를 위한 안내서
> 작성: 김관우 (PM & Tech Writer) · v1.0 (13주차, 2026.10.07)

---

## 1. 관제탑이 하는 일

관제탑은 네트워크가 공격을 스스로 막는 과정을 실시간으로 보여주는 웹 화면이다. 운영자는 평소에는 지켜보기만 하면 되고, 자동 방어가 잘못 동작할 때만 **비상 수동 제어**로 개입한다.

## 2. 실행 방법

| 모드 | 용도 | 실행 |
|:---|:---|:---|
| 더미(mock) | 시연 연습, 화면 개발 | `uv run uvicorn api.main:app --port 8000` |
| 실데이터(live) | Mininet·Ryu·Redis 연동 | `SDN_MOCK=0 REDIS_URL=redis://localhost:6379/0 uv run uvicorn api.main:app --port 8000` |

웹 화면은 `cd ui && npm install && npm run dev` 후 브라우저에서 `http://localhost:5173`을 연다.
수동 제어를 아무나 쓰지 못하게 하려면 백엔드 실행 전에 `export SDN_ADMIN_TOKEN=<비밀값>`을 설정한다.

## 3. 화면 구성

```
┌─────────────────────────────────────────────────────────────────────┐
│ 관제탑 대시보드     [데이터 출처] [방어 단계] [연결 상태] [비상 수동 제어] │ ← 헤더
├─────────────────────────────────────────────────────────────────────┤
│ ● 상태 스트립 (평상시 안내 / 적색 경보 / 격리 / 복구 카운트다운)          │
├──────────────────────────────────────┬──────────────────────────────┤
│ 토폴로지 지도                         │ 보안 이벤트 (ms 단위 기록)      │
├──────────────────────┬───────────────┴──────────────────────────────┤
│ 초당 패킷 수 (PPS)    │ 패킷당 평균 크기 (BPP)                         │
├──────────────────────┴──────────────────────────────────────────────┤
│ 포트 텔레메트리 표                                                    │
└─────────────────────────────────────────────────────────────────────┘
```

### 3.1 헤더 배지

| 배지 | 의미 |
|:---|:---|
| `MOCK DATA` / `LIVE · REDIS` / `REDIS OFFLINE` | 데이터 출처. 실데이터 모드에서 Redis가 끊기면 `REDIS OFFLINE`(주황) |
| 방어 단계 | 아래 4장의 다섯 단계 중 현재 단계 |
| `WS CONNECTED` (초록) | 관제탑 서버와 연결됨 |
| `WS RECONNECTING · n` (노랑) | 연결 끊김, n번째 재시도 중 (간격을 점점 늘려 자동 재시도) |
| `WS DISCONNECTED · n` (빨강) | 5번 넘게 실패. 재시도는 계속되므로 서버만 다시 켜면 자동 복구 |

### 3.2 토폴로지 지도

| 표시 | 의미 |
|:---|:---|
| 초록 테두리 | 정상 |
| 빨간 테두리 | 공격 받음 |
| 하늘색 테두리 | 격리됨 |
| 굵은 파란 선 (빛남) | 우회 경로 (S1 → S3 → S4) |
| 회색 점선 | 차단된 링크 |

노드를 드래그해 배치를 바꿀 수 있고, 노드를 클릭하면 아래에 포트별 PPS가 나온다.

### 3.3 차트와 포트 표

- **PPS 차트:** 정상 사용자(파랑)와 공격자(주황) 포트의 초당 패킷 수. 공격 때 주황 선이 수천으로 치솟는다.
- **BPP 차트:** 패킷당 평균 크기. 정상은 500B 이상, SYN Flood는 약 64B로 떨어진다. **공격 판별의 핵심 지표**다.
- 차트 위 한 줄에 각 포트의 최신값이 숫자로 나온다.
- **포트 표:** 모든 스위치 포트의 PPS·bps·BPP. 공격 의심 포트는 빨간 글씨와 ⚠, 공격 유입 포트는 행 전체가 깜빡인다.

## 4. 방어 단계별로 보이는 것

| 단계 (배지) | 상태 스트립 | 운영자 할 일 |
|:---|:---|:---|
| `SYSTEM CALIBRATING` | 노랑 "기준 트래픽 학습 중" (시작 후 15초) | 기다린다 |
| `NORMAL` | "정상 · 감지된 위협 없음" | 지켜본다 |
| `UNDER ATTACK` | **빨간 점멸 경보** · 위협 유형, 유입 포트, 스코어, PPS, BPP, 탐지 시각 | 자동 방어가 곧 동작한다. 유입 포트가 정상 호스트(S1:1, S4:1)면 오탐을 의심한다 |
| `MITIGATED` | **파란 스트립** · 격리 포트, 우회 경로, 탐지→격리 시간 | 정상 트래픽(파란 선)이 S3로 우회 중인지 확인 |
| `RESTORING` | **청록 스트립** · 복구까지 남은 초, 진행 막대 | 기다린다. 공격이 다시 오면 자동으로 `MITIGATED`로 돌아간다 |
| `NORMAL` (복구 후) | 우측 하단 **자가 복구 완료 알림** (탐지~복구 시각, 총 소요) | "확인"으로 닫는다 (15초 후 자동으로 닫힘) |

## 5. 비상 수동 제어

자동 방어가 잘못 동작할 때만 쓴다. 예:
- AI가 정상 사용자 포트를 공격으로 오인해 격리했다 → **복원**
- 공격이 분명한데 자동 격리가 되지 않았다 → **격리**

### 5.1 사용 순서

1. 헤더 오른쪽 **[비상 수동 제어]** 버튼을 누른다.
2. **동작**을 고른다: 격리(차단) 또는 복원(차단 해제).
3. **대상 포트**를 고른다: S1:2(공격자), S1:1(정상 사용자), S4:1(서버). 정상 호스트를 격리하려 하면 주황 경고가 나온다.
4. **사유**를 쓴다 (3자 이상, 필수). 보안 이벤트에 그대로 기록된다.
5. 관리자 토큰을 설정했다면 입력한다.
6. 확인 체크박스를 켜야 실행 버튼이 활성화된다.
7. **실행**을 누르면 좌측 하단에 전송 알림이 뜨고, 보안 이벤트에 주황 `MANUAL` 항목이 쌓인다.

`Esc` 또는 바깥 영역 클릭으로 언제든 취소할 수 있다.

### 5.2 안전장치

| 장치 | 내용 |
|:---|:---|
| 트렁크 포트 차단 | 스위치끼리 연결된 포트는 목록에 없고, API로 직접 보내도 거부(409)된다 |
| 우회는 자동 전용 | 수동 제어는 격리·복원만 가능하다 |
| 사유 필수 | 모든 수동 조작이 누가·왜 했는지 기록된다 (`[MANUAL] 운영자: 사유`) |
| 관리자 토큰 | `SDN_ADMIN_TOKEN` 설정 시 토큰이 맞아야만 실행된다 (틀리면 401) |
| Redis 장애 | 실데이터 모드에서 Redis에 연결할 수 없으면 명령을 보내지 않고 오류(503)를 알린다 |

### 5.3 API로 직접 보내기 (선택)

```bash
curl -X POST http://localhost:8000/api/control/manual \
  -H "Content-Type: application/json" -H "X-Admin-Token: <토큰>" \
  -d '{"action":"RESTORE","dpid":1,"port":1,"reason":"AI 오탐으로 수동 복원","operator":"김관우"}'
```

## 6. 문제 해결

| 증상 | 원인 | 조치 |
|:---|:---|:---|
| 배지가 `WS RECONNECTING` | 관제탑 서버(8000번)가 꺼짐 | 백엔드를 다시 실행. 화면은 새로고침 없이 자동 복구 |
| `REDIS OFFLINE` | 실데이터 모드에서 Redis 꺼짐 | `redis-server` 실행 (Docker: `docker compose up redis-broker`) |
| 차트에 "포트 통계 수신 대기 중" | 통계가 아직 2개 이상 들어오지 않음 | 2~4초 기다림. 실데이터 모드면 Ryu 실행 여부 확인 |
| 수동 제어가 "관리자 토큰이 올바르지 않습니다" | 토큰 불일치 | 백엔드 실행 시 설정한 `SDN_ADMIN_TOKEN` 값 입력 |
| 수동 제어가 "트렁크 포트라 수동 제어할 수 없습니다" | 스위치 간 포트를 지정함 | 호스트 포트(S1:1, S1:2, S4:1)만 제어 가능 |
| 화면이 끊김 | 저사양 PC | `cd ui && npm run build && npm run perf`로 측정 (기준: 평균 58fps 이상) |
