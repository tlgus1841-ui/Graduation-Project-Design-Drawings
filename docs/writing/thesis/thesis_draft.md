### 초록 (Abstract)
현대 네트워크 인프라에서 발신지 IP 변조(IP Spoofing)를 동반한 분산 서비스 거부(DDoS) 공격은 기존 인라인 방화벽과 침입 방지 시스템(IPS)의 플로우 테이블 메모리 고갈을 유발하고, 관리자의 수동 개입에 의존하는 복구 체계로 인해 심각한 서비스 중단 시간을 초래한다. 본 논문에서는 소프트웨어 정의 네트워킹(SDN)의 중앙 집중식 제어력과 경량 머신러닝 이상 탐지 알고리즘을 결합한 자율 치유형 관제 시스템 'Self-Defending SDN Tower'를 제안하고 실증한다.  
제안하는 시스템은 (1) 스위치 포트 대역폭의 2-Tier 비동기 모니터링을 통해 컨트롤러 오버헤드를 최소화하고, (2) 실시간 5대 파생 피처 기반의 Isolation Forest 비지도 학습으로 밀리초 단위의 이상 트래픽을 탐지한다. (3) 탐지 즉시 가변적인 IP 대신 물리/가상 인그레스 포트(`in_port`) 기반의 정밀 격리 규칙을 주입하여 플로우 테이블 폭발을 방지하며, (4) 다중 경로 토폴로지 상에서 피해 링크의 정상 플로우를 Dijkstra 기반 대체 경로로 무유실(`Packet Loss 0%`) 우회 전환한다. 마지막으로 (5) 위협 소멸 시 FSM(상태 전이 머신) 타임아웃을 통해 최단 경로로 자가 복구하는 5단계 폐루프(Closed-Loop)를 달성한다. Mininet 가상 에뮬레이션 환경에서의 실험 결과, IP 스푸핑 공격 발생 후 [ ]초 이내에 자율 격리 및 우회가 완료되었으며 정상 트래픽의 연속성이 유지됨을 검증하였다.

**주제어(Keywords):** 소프트웨어 정의 네트워킹 (SDN), OpenFlow 1.3, 이상 트래픽 탐지, Isolation Forest, IP 스푸핑 방어, 자율 라우팅, 실시간 관제탑

본 장은 공격 탐지 이후 시스템이 사람의 개입 없이 **격리 → 우회 → 복구**를 수행하는 방식을 다룬다. 전체 동작은 5개 상태(`CALIBRATING`, `NORMAL`, `ATTACK_DETECTED`, `MITIGATED`, `COOLDOWN_VERIFY`)를 갖는 유한 상태 기계(FSM)로 정의되며, 각 절은 이 상태 전이 중 하나에 대응한다.

### 4.1 경량 2-Tier 텔레메트리 파이프라인

이상 탐지의 입력은 개별 패킷이 아니라 **스위치 포트 단위의 누적 카운터**다. 컨트롤러는 2초 주기로 모든 스위치에 `OFPPortStatsRequest`를 보내고, 응답(`OFPPortStatsReply`)의 포트별 수신 패킷·바이트·오류 수를 Redis `sdn:stats:port` 채널에 발행한다(1단계: 스위치 → 컨트롤러). 피처 계산기와 관제탑 백엔드는 이 채널을 구독해 각각 탐지와 시각화에 사용한다(2단계: 컨트롤러 → Redis → 소비자).

패킷마다 컨트롤러를 거치는 방식과 달리, 이 구조는 공격 트래픽의 양과 무관하게 컨트롤러 부하가 "스위치 수 × 2초당 1회"로 일정하다. 피처 계산기는 직전 관측치와의 차이로 다음 5개 파생 피처를 만든다.

| 피처 | 정의 | 공격 시 특징 |
|:---|:---|:---|
| ΔPPS | Δ수신 패킷 / Δt | 수천 단위로 급증 |
| ΔBPS | Δ수신 바이트 × 8 / Δt | 증가하지만 PPS보다 완만 |
| BPP | Δ바이트 / Δ패킷 | SYN 패킷만 있어 54~74B로 급감 (정상 500B 이상) |
| 오류율 | Δ수신 오류 / Δ패킷 | 보조 지표 |
| 지속 시간 | 포트 활성 시간 | 맥락 정보 |

탐지 조건은 BPP ≤ 80B와 Isolation Forest 이상 스코어 < -0.5가 **2주기 연속** 충족되는 경우다. 연속 조건은 정상 트래픽의 순간 급증(Flash Crowd)을 공격으로 오인하지 않기 위한 것이다.

### 4.2 In_port 기반 스푸핑 방어 및 Access/Trunk 포트 격리 가드레일

IP 스푸핑 공격은 패킷마다 출발지 IP를 바꾼다. 출발지 IP나 5-튜플로 차단 규칙을 만들면 공격 패킷 수만큼 규칙이 생겨 스위치 플로우 테이블이 고갈된다. 본 시스템은 두 가지로 이를 막는다.

1. **포워딩 규칙은 목적지 IP만으로 만든다.** 출발지가 몇 개든 서버로 가는 규칙은 하나다. 실측 결과 공격 패킷 18,103개(약 1,571 PPS) 동안 S1~S4의 플로우 개수 증가는 0이었고, 공격 패킷 전부가 `nw_dst=10.0.0.4` 규칙 하나에 매칭되었다(9주차 검증서).
2. **차단은 공격이 들어오는 물리 포트(`in_port`) 단위로 한다.** IP가 아무리 바뀌어도 같은 포트로 들어오므로 Priority 100의 Drop 규칙 하나로 막을 수 있다. 차단 규칙은 기본 경로 규칙(Priority 10)보다 우선한다.

단, 스위치끼리 연결된 트렁크 포트를 차단하면 망 전체가 끊긴다. 따라서 차단 대상은 호스트가 연결된 액세스 포트로 제한하며, 트렁크 포트에 대한 ISOLATE 명령은 화이트리스트 가드레일에서 거부한다.

### 4.3 동적 우회 라우팅과 무유실 전환

공격 포트를 격리하는 동안 정상 사용자의 트래픽은 기본 경로(S1 → S2 → S4) 대신 우회 경로(S1 → S3 → S4)로 옮겨진다. 경로 전환 순간에 패킷이 유실되지 않도록, 우회 규칙은 **하류 스위치부터** 설치한다.

| 순서 | 스위치 | 규칙 |
|:---:|:---:|:---|
| 1 | S3 | 서버행 → S4, 복귀 → S1 |
| 2 | S4 | 복귀 트래픽 → S3 |
| 3 | S1 | 서버행 → S3 (마지막) |

입구 스위치 S1이 길을 바꾸는 순간 하류에는 이미 규칙이 있으므로 전환 직후 첫 패킷부터 끊김 없이 전달된다(make-before-break). 10ms 간격 ping 1,000개를 보내는 도중 경로를 전환하는 실험을 4회 반복한 결과 **4,000개 중 손실 0개**였고, 회당 약 800개가 실제로 우회 규칙을 통과했다(10주차 검증서). 다중 경로 일반화를 위한 Dijkstra 기반 경로 계산은 같은 설치 순서 원칙을 따른다.

### 4.4 FSM 기반 플래핑(Flapping) 방지 및 안전 롤백 메커니즘

공격이 끝나면 차단과 우회를 해제해 기본 경로로 돌아가야 한다. 그러나 공격이 잠깐 멈췄다 다시 오는 경우 즉시 해제하면 차단과 해제가 반복되는 **플래핑**이 발생한다. 본 시스템은 다음 규칙으로 이를 막는다.

- 차단·우회 규칙에 타임아웃을 두지 않는다(`idle_timeout = hard_timeout = 0`). 해제는 명시적 `RESTORE` 명령으로만 한다.
- 공격 소멸(S1:2 PPS < 100, 스코어 ≥ -0.5)이 확인되면 `COOLDOWN_VERIFY`로 진입하고, **10초 동안 정상 판정이 유지될 때만** 해제한다.
- 쿨다운 중 공격 조건이 다시 충족되면 해제 없이 `MITIGATED`로 돌아가고 타이머를 처음부터 다시 센다.

5가지 시나리오(지속 공격, 쿨다운 중 재공격, 4초 간격 맥동 공격, 단발 스파이크, 정상 급증)로 명세 FSM을 시험한 결과 모든 경우 플래핑은 0회였다. 같은 시나리오에서 쿨다운이 없는 타임아웃식 FSM은 맥동 공격 60초 동안 차단과 해제를 8회씩 반복했다(11주차 검증서). 지속 공격 종료 후 복구까지는 공격 소멸 확인 샘플(2초)과 쿨다운(10초)을 합쳐 12초가 걸렸다.

관제탑은 각 상태를 색으로 구분해 표시한다. 공격 탐지 시 적색 경보가 점멸하고, 격리 후에는 청색으로 우회 경로를 강조하며, 쿨다운 중에는 남은 시간을 표시한다. 복구가 끝나면 탐지부터 복구 완료까지의 시각을 밀리초 단위로 정리한 알림을 띄운다.
