### 초록 (Abstract)
현대 네트워크 인프라에서 발신지 IP 변조(IP Spoofing)를 동반한 분산 서비스 거부(DDoS) 공격은 기존 인라인 방화벽과 침입 방지 시스템(IPS)의 플로우 테이블 메모리 고갈을 유발하고, 관리자의 수동 개입에 의존하는 복구 체계로 인해 심각한 서비스 중단 시간을 초래한다. 본 논문에서는 소프트웨어 정의 네트워킹(SDN)의 중앙 집중식 제어력과 경량 머신러닝 이상 탐지 알고리즘을 결합한 자율 치유형 관제 시스템 'Self-Defending SDN Tower'를 제안하고 실증한다.  
제안하는 시스템은 (1) 스위치 포트 대역폭의 2-Tier 비동기 모니터링을 통해 컨트롤러 오버헤드를 최소화하고, (2) 실시간 5대 파생 피처 기반의 Isolation Forest 비지도 학습으로 밀리초 단위의 이상 트래픽을 탐지한다. (3) 탐지 즉시 가변적인 IP 대신 물리/가상 인그레스 포트(`in_port`) 기반의 정밀 격리 규칙을 주입하여 플로우 테이블 폭발을 방지하며, (4) 다중 경로 토폴로지 상에서 피해 링크의 정상 플로우를 Dijkstra 기반 대체 경로로 무유실(`Packet Loss 0%`) 우회 전환한다. 마지막으로 (5) 위협 소멸 후 상태 전이 머신(FSM)이 10초 쿨다운 동안 정상 상태가 유지됨을 확인한 뒤에만 기본 경로로 자가 복구하여, 차단과 해제가 반복되는 플래핑을 막는 5단계 폐루프(Closed-Loop)를 달성한다. Mininet 가상 에뮬레이션 환경에서 4단계 종합 시나리오를 3회 반복한 결과, 공격 시작 후 평균 약 3.8초 이내(2초 주기 통계 2회 연속 확인 포함)에 자율 격리 및 우회가 완료되었고, 탐지 확정에서 규칙 설치까지는 평균 78.4ms가 걸렸다. 공격 중 정상 트래픽 손실은 0%(0 / 4,312), 격리 후 서버에 도달한 공격 패킷은 0개였다. 단, 이 종합 실험의 탐지와 방어 실행은 명세를 그대로 옮긴 임시 구성요소로 수행하였다.

**주제어(Keywords):** 소프트웨어 정의 네트워킹 (SDN), OpenFlow 1.3, 이상 트래픽 탐지, Isolation Forest, IP 스푸핑 방어, 자율 라우팅, 실시간 관제탑

## 1. 서론 (Introduction)
> *초안 v0.1 (12주차, 김관우)*

### 1.1 연구 배경 및 문제 제기

분산 서비스 거부(DDoS) 공격 중 SYN Flood는 TCP 연결 요청(SYN)만 대량으로 보내 서버가 응답 대기 상태에 자원을 소진하게 만드는 공격이다. 공격자가 패킷마다 출발지 IP를 무작위로 바꾸는 IP 스푸핑을 함께 쓰면, "특정 IP를 차단한다"는 전통적인 방어는 사실상 무력해진다. 차단 대상이 될 IP가 매 패킷 달라지기 때문이다.

기존 네트워크 장비는 경로와 정책이 장비마다 고정되어 있어, 공격을 탐지하더라도 차단 규칙 설정과 우회 경로 변경을 관리자가 직접 수행해야 한다. 이 과정에서 탐지와 대응 사이에 사람의 판단 시간이 끼어들고, 그동안 정상 사용자의 서비스도 함께 중단된다. 또 출발지 IP 단위로 규칙을 만드는 장비는 스푸핑 공격을 받으면 공격 패킷 수만큼 규칙이 생겨 플로우 테이블이 고갈되는 문제도 있다.

### 1.2 연구 목적

본 연구는 소프트웨어 정의 네트워킹(SDN)의 중앙 제어 구조를 이용해, 공격 탐지부터 격리·우회·복구까지를 **사람의 개입 없이** 수행하는 자율 방어 관제 시스템 *Self-Defending SDN Tower*를 구현하고 실측으로 검증하는 것을 목표로 한다. 구체적인 목표 지표는 다음과 같다.

| 목표 | 지표 |
|:---|:---|
| 신속한 대응 | 탐지 후 방어 반응 시간 ≤ 100ms |
| 정상 서비스 연속성 | 방어 중 정상 트래픽 손실률 ≤ 2% |
| 정확한 탐지 | 이상 탐지 F1-Score ≥ 0.95 |
| 안정적 복구 | 공격 종료 후 플래핑 없는 자동 복구 |

### 1.3 연구 범위와 기여

본 연구는 Mininet 가상 네트워크 위의 4-스위치 다이아몬드 토폴로지를 실험 대상으로 하며, 주요 기여는 다음과 같다.

1. **스푸핑에 강한 포트 단위 격리:** 출발지 IP 대신 공격이 들어오는 스위치 포트(`in_port`)를 차단해, IP가 바뀌어도 차단 규칙 하나로 막고 플로우 테이블 폭발을 방지한다.
2. **무유실 우회 전환:** 하류 스위치부터 규칙을 설치하는 순서로 경로를 바꿔, 전환 순간에도 정상 패킷을 잃지 않는다.
3. **플래핑 없는 자가 복구:** 쿨다운 검증 후 명시적으로 해제하는 FSM으로, 간헐적 공격에도 차단·해제를 반복하지 않는다.
4. **실시간 관제탑:** 탐지·격리·우회·복구 전 과정을 밀리초 단위 타임라인과 색상 상태로 보여주는 웹 대시보드를 제공한다.

## 2. 관련 연구 (Related Works)
> 💡 *참조 자료: `docs/study/01_` ~ `08_` 스터디 문서. 선행 연구 비교(2.3)는 문헌 조사 후 보강한다.*

### 2.1 소프트웨어 정의 네트워킹 및 OpenFlow 프로토콜

SDN은 패킷을 전달하는 데이터 평면(스위치)과 전달 규칙을 결정하는 제어 평면(컨트롤러)을 분리한 구조다. 스위치는 컨트롤러가 내려준 플로우 규칙(일치 조건 + 동작 + 우선순위)에 따라 패킷을 처리하고, 일치하는 규칙이 없으면 패킷을 컨트롤러로 올린다(PacketIn). OpenFlow는 이 둘 사이의 표준 프로토콜이며[1], 본 연구는 OpenFlow 1.3과 Ryu 컨트롤러[3]를 사용한다. 컨트롤러가 망 전체를 보고 규칙을 즉시 바꿀 수 있다는 점이 자율 방어의 전제가 된다.

### 2.2 SDN 환경에서의 이상 탐지와 Isolation Forest

Isolation Forest는 데이터를 무작위로 분할할 때 이상치가 정상 데이터보다 적은 분할로 고립된다는 성질을 이용하는 비지도 이상 탐지 기법이다[2]. 정상 트래픽만으로 학습할 수 있어 공격 라벨이 부족한 환경에 적합하고, 추론 비용이 낮아 2초 주기의 실시간 판정에 쓸 수 있다. 본 연구는 포트 통계에서 계산한 5개 파생 피처를 입력으로 사용한다(4.1절).

### 2.3 기존 자가 치유 및 동적 우회 연구와의 차별성

*(문헌 조사 후 작성 예정)* 비교 축: ① 차단 단위(IP·플로우 vs 포트), ② 우회 전환 시 유실 측정 여부, ③ 복구 방식(타임아웃 vs 검증 후 명시적 해제), ④ 운영자 가시화 제공 여부.

## 3. 시스템 아키텍처 및 설계 (System Architecture)
> 💡 *참조 자료: `docs/planning/roadmap_v2.md`, `harness/contracts/sdn_events.py`, `docs/specs/defense_scenarios.md`*

### 3.1 전체 계층 구조

시스템은 네 계층으로 구성된다.

| 계층 | 구성 요소 | 역할 |
|:---|:---|:---|
| 데이터 평면 | Mininet, Open vSwitch (S1~S4), 호스트 3대 | 실제 패킷 전달, 포트 통계 제공 |
| 제어 평면 | Ryu 4.34 컨트롤러 | 경로 규칙 설치, Proxy ARP, 2초 주기 통계 수집, 방어 명령 실행 |
| 분석 계층 | 피처 계산기, Isolation Forest 워커 | 5대 파생 피처 계산, 이상 스코어 산출, 탐지 알림 발행 |
| 웹 계층 | FastAPI 백엔드, React 관제탑 | 실시간 중계, 상태·경보·타임라인 시각화 |

실험 토폴로지는 다이아몬드 형태다. 입구 스위치 S1에 정상 사용자(H_legit, 포트 1)와 공격자(H_attacker, 포트 2)가 연결되고, 출구 스위치 S4에 서버(H_server)가 연결된다. S1에서 S4로 가는 길은 기본 경로(S2 경유)와 우회 경로(S3 경유) 두 개다. 경로가 두 개라야 공격 포트를 막는 동안 정상 트래픽을 다른 길로 보낼 수 있다.

### 3.2 Contract-First 비동기 IPC 버스 설계

계층 간 통신은 Redis Pub/Sub의 네 채널로 이루어지며, 모든 메시지 형식은 Pydantic 모델 하나(`harness/contracts/sdn_events.py`)에 정의해 팀원 모두가 같은 규격을 쓴다(Single Source of Truth).

| 채널 | 발행 | 구독 | 내용 |
|:---|:---|:---|:---|
| `sdn:stats:port` | 컨트롤러 | 피처 계산기, 웹 | 스위치별 포트 누적 카운터 |
| `sdn:anomaly:alert` | AI 워커 | 컨트롤러, 웹 | 공격 포트, 위협 유형, 스코어, PPS·BPP |
| `sdn:control:command` | 방어 FSM | 컨트롤러, 웹 | ISOLATE·REROUTE·RESTORE 명령 |
| `sdn:topology:sync` | 컨트롤러 | 웹 | 노드·링크 상태 |

웹 백엔드는 이 채널들을 구독해 검증한 뒤 `{type, data}` 형태로 브라우저에 WebSocket으로 전달한다. 형식이 맞지 않는 메시지는 버리고 기록만 남겨, 한 구성 요소의 오류가 관제탑 전체로 번지지 않게 했다. 규격을 먼저 고정한 덕분에 각 계층을 더미 데이터로 독립 개발한 뒤 그대로 연결할 수 있었다.

### 3.3 실시간 5대 파생 피처 엔지니어링

피처의 정의와 탐지 조건은 4.1절에서 다룬다. 설계상 핵심은 개별 패킷을 보지 않고 **포트 카운터의 2초 간 차이**만 쓴다는 점이다. 이 덕분에 분석 비용이 공격 트래픽 양과 무관하게 일정하다.

## 4. 자가 방어 및 자율 라우팅 메커니즘 (Defense & Self-Healing)
> 💡 *참조 자료: `docs/specs/defense_scenarios.md`, `docs/writing/reports/verification/week09~11_*.md`*
>
> *초안 v0.1 (11주차, 김관우). 4.2·4.3의 컨트롤러 측 구현(In_port 차단, Dijkstra 우회)은 9·10주차 구현 완료 후 수치를 갱신한다.*

본 장은 공격 탐지 이후 시스템이 사람의 개입 없이 **격리 → 우회 → 복구**를 수행하는 방식을 다룬다. 전체 동작은 5개 상태(`CALIBRATING`, `NORMAL`, `ATTACK_DETECTED`, `MITIGATED`, `COOLDOWN_VERIFY`)를 갖는 유한 상태 기계(FSM)로 정의되며, 각 절은 이 상태 전이 중 하나에 대응한다.

### 4.1 경량 2-Tier 텔레메트리 파이프라인

이상 탐지의 입력은 개별 패킷이 아니라 **스위치 포트 단위의 누적 카운터**다. 컨트롤러는 2초 주기로 모든 스위치에 `OFPPortStatsRequest`를 보내고, 응답(`OFPPortStatsReply`)의 포트별 수신 패킷·바이트·오류 수를 Redis `sdn:stats:port` 채널에 발행한다(1단계: 스위치 → 컨트롤러). 피처 계산기와 관제탑 백엔드는 이 채널을 구독해 각각 탐지와 시각화에 사용한다(2단계: 컨트롤러 → Redis → 소비자).

패킷마다 컨트롤러를 거치는 방식과 달리, 이 구조는 공격 트래픽의 양과 무관하게 컨트롤러 부하가 "스위치 수 × 2초당 1회"로 일정하다. 피처 계산기는 직전 관측치와의 차이로 다음 5개 파생 피처를 만든다.

| 피처 | 정의 | 공격 시 특징 |
|:---|:---|:---|
| ΔPPS | Δ수신 패킷 / Δt | 수천 단위로 급증 |
| ΔBPS | Δ수신 바이트 × 8 / Δt | 증가하지만 PPS보다 완만 |
| BPP | Δ바이트 / Δ패킷 | SYN 패킷만 있어 54~74B로 급감 (정상 500B 이상) |
| 오류율 | Δ수신 오류 / Δ패킷 | 보조 지표 |
| 지속 시간 | 포트 활성 시간 | 맥락 정보 |

탐지 조건은 BPP ≤ 80B와 Isolation Forest 이상 스코어 < -0.5가 **2주기 연속** 충족되는 경우다. 연속 조건은 정상 트래픽의 순간 급증(Flash Crowd)을 공격으로 오인하지 않기 위한 것이다.

### 4.2 In_port 기반 스푸핑 방어 및 Access/Trunk 포트 격리 가드레일

IP 스푸핑 공격은 패킷마다 출발지 IP를 바꾼다. 출발지 IP나 5-튜플로 차단 규칙을 만들면 공격 패킷 수만큼 규칙이 생겨 스위치 플로우 테이블이 고갈된다. 본 시스템은 두 가지로 이를 막는다.

1. **포워딩 규칙은 목적지 IP만으로 만든다.** 출발지가 몇 개든 서버로 가는 규칙은 하나다. 실측 결과 공격 패킷 18,103개(약 1,571 PPS) 동안 S1~S4의 플로우 개수 증가는 0이었고, 공격 패킷 전부가 `nw_dst=10.0.0.4` 규칙 하나에 매칭되었다(9주차 검증서).
2. **차단은 공격이 들어오는 물리 포트(`in_port`) 단위로 한다.** IP가 아무리 바뀌어도 같은 포트로 들어오므로 Drop 규칙 하나로 막을 수 있다. 이 규칙은 기본 경로(Priority 10)뿐 아니라 **우회 규칙(Priority 100)보다도 높은 우선순위**를 가져야 한다. 공격 패킷은 서버로 향하므로 우회 규칙의 일치 조건(목적지 IP)에도 해당하기 때문이다. 두 규칙의 우선순위가 같으면 어느 쪽이 적용될지 정해지지 않으며, 실측에서는 공격 패킷이 우회 경로로 서버에 도달했다(5.5절).

단, 스위치끼리 연결된 트렁크 포트를 차단하면 망 전체가 끊긴다. 따라서 차단 대상은 호스트가 연결된 액세스 포트로 제한하며, 트렁크 포트에 대한 ISOLATE 명령은 화이트리스트 가드레일에서 거부한다.

### 4.3 동적 우회 라우팅과 무유실 전환

공격 포트를 격리하는 동안 정상 사용자의 트래픽은 기본 경로(S1 → S2 → S4) 대신 우회 경로(S1 → S3 → S4)로 옮겨진다. 경로 전환 순간에 패킷이 유실되지 않도록, 우회 규칙은 **하류 스위치부터** 설치한다.

| 순서 | 스위치 | 규칙 |
|:---:|:---:|:---|
| 1 | S3 | 서버행 → S4, 복귀 → S1 |
| 2 | S4 | 복귀 트래픽 → S3 |
| 3 | S1 | 서버행 → S3 (마지막) |

입구 스위치 S1이 길을 바꾸는 순간 하류에는 이미 규칙이 있으므로 전환 직후 첫 패킷부터 끊김 없이 전달된다(make-before-break). 10ms 간격 ping 1,000개를 보내는 도중 경로를 전환하는 실험을 4회 반복한 결과 **4,000개 중 손실 0개**였고, 회당 약 800개가 실제로 우회 규칙을 통과했다(10주차 검증서). 다중 경로 일반화를 위한 Dijkstra 기반 경로 계산은 같은 설치 순서 원칙을 따른다.

### 4.4 FSM 기반 플래핑(Flapping) 방지 및 안전 롤백 메커니즘

공격이 끝나면 차단과 우회를 해제해 기본 경로로 돌아가야 한다. 그러나 공격이 잠깐 멈췄다 다시 오는 경우 즉시 해제하면 차단과 해제가 반복되는 **플래핑**이 발생한다. 본 시스템은 다음 규칙으로 이를 막는다.

- 차단·우회 규칙에 타임아웃을 두지 않는다(`idle_timeout = hard_timeout = 0`). 해제는 명시적 `RESTORE` 명령으로만 한다.
- 공격 소멸(S1:2 PPS < 100, 스코어 ≥ -0.5)이 확인되면 `COOLDOWN_VERIFY`로 진입하고, **10초 동안 정상 판정이 유지될 때만** 해제한다.
- 쿨다운 중 공격 조건이 다시 충족되면 해제 없이 `MITIGATED`로 돌아가고 타이머를 처음부터 다시 센다.

5가지 시나리오(지속 공격, 쿨다운 중 재공격, 4초 간격 맥동 공격, 단발 스파이크, 정상 급증)로 명세 FSM을 시험한 결과 모든 경우 플래핑은 0회였다. 같은 시나리오에서 쿨다운이 없는 타임아웃식 FSM은 맥동 공격 60초 동안 차단과 해제를 8회씩 반복했다(11주차 검증서). 지속 공격 종료 후 복구까지는 공격 소멸 확인 샘플(2초)과 쿨다운(10초)을 합쳐 12초가 걸렸다.

관제탑은 각 상태를 색으로 구분해 표시한다. 공격 탐지 시 적색 경보가 점멸하고, 격리 후에는 청색으로 우회 경로를 강조하며, 쿨다운 중에는 남은 시간을 표시한다. 복구가 끝나면 탐지부터 복구 완료까지의 시각을 밀리초 단위로 정리한 알림을 띄운다.

## 6. 결론 및 향후 과제 (Conclusion & Future Work)
> *초안 v0.1 (16주차, 김관우)*

### 6.1 결론

본 연구는 IP 스푸핑 SYN Flood에 대해 탐지 → 격리 → 우회 → 복구를 사람 개입 없이 수행하는 SDN 자율 방어 시스템 Self-Defending SDN Tower를 설계하고 Mininet 위에서 실증하였다. 주요 결과는 다음과 같다.

1. **포트 기반 격리의 효과.** 출발지 IP 대신 공격이 유입된 접속 포트(`in_port`)를 차단하여, 위조 패킷 18,103개가 들어오는 동안 스위치 플로우 규칙이 하나도 늘지 않았다. IP 단위 차단이 갖는 플로우 테이블 고갈 문제를 규칙 1개로 해결하였다.
2. **무유실 경로 전환.** 우회 규칙을 하류 스위치부터 설치하고 입구 스위치를 마지막에 바꾸는 순서로, 경로 전환 중 정상 패킷 4,000개 중 손실이 0개였다.
3. **플래핑 없는 자가 복구.** 2회 연속 확인 후 차단하고 10초 쿨다운으로 해제를 검증하는 FSM은 5개 시나리오에서 플래핑 0회를 기록하였다. 쿨다운이 없는 방식은 같은 맥동 공격에서 차단과 해제를 8회씩 반복하였다.
4. **종합 성능.** 4단계 시나리오 3회에서 탐지 확정 → 차단·우회 설치 평균 78.4ms, 공격 중 정상 트래픽 손실 0%, 격리 후 서버 도달 공격 0, 공격 종료 → 자동 복구 평균 12.73초였다.
5. **관측 가능성.** 웹 관제탑이 경보, 격리, 우회, 쿨다운, 복구 전 과정을 실시간으로 보여주며, CPU 성능을 4배 낮춘 조건에서도 56.6fps를 유지하였다.

또한 검증 과정에서 차단 규칙과 우회 규칙의 우선순위가 같으면 공격 패킷이 우회 경로를 타고 서버에 도달하는 설계 결함을 발견하였다. SDN에서 목적이 다른 규칙이 같은 패킷에 겹칠 수 있으므로, 방어 규칙 간 우선순위 설계가 개별 기능만큼 중요하다는 점을 실험으로 확인하였다.

| 임시 구성요소 | 종합 실험의 AI 탐지는 규칙(BPP ≤ 80B, ΔPPS ≥ 500), FSM은 명세 참조 구현, 방어 실행은 `ovs-ofctl`로 대체하였다. | F1-Score와 컨트롤러 FlowMod 기준 반응 시간은 아직 측정되지 않았다. |
| 고정 우회 경로 | 우회 경로는 다이아몬드 토폴로지의 S1 → S3 → S4로 고정하였다. | 임의 토폴로지에서의 경로 계산은 검증하지 않았다. |
| 탐지 주기 | 2초 통계 주기와 2회 연속 확인 규칙 때문에 공격 시작에서 격리까지 약 3.8초가 걸린다. | 이 구간 동안 공격 트래픽은 서버에 도달한다. |
| 실험 환경 | OVS 유저스페이스 데이터패스, 단일 공격자, 4개 스위치 | 처리 속도와 대규모 환경 동작은 커널 데이터패스·실장비와 다를 수 있다. |
| 공격 유형 | 단일 접속 포트에서 들어오는 스푸핑 SYN Flood만 다루었다. | 여러 포트에 분산된 공격, 정상 사용자와 같은 포트를 쓰는 공격은 범위 밖이다. |

### 6.3 향후 과제

1. Isolation Forest 모델과 컨트롤러 내장 FSM·방어 실행을 연동하고, 같은 4단계 시나리오로 F1-Score와 반응 시간을 재측정한다.
2. 차단 규칙 우선순위를 우회보다 높게 두는 명세 수정(Q5)을 확정하고 컨트롤러에 반영한다.
3. 토폴로지 정보로 우회 경로를 계산하는 기능(Dijkstra 등)을 넣고, 스위치 수를 늘린 토폴로지에서 무유실 전환 순서가 유지되는지 검증한다.
4. 통계 주기 단축과 컨트롤러 부하의 관계를 측정해 공격 시작 → 격리 시간을 줄인다.
5. 분산 공격, 저속 공격 등 공격 유형을 넓히고 캡스톤 최종 전시용으로 시연을 고도화한다.
