## 1. 검증 목적

공격 포트를 격리할 때 정상 사용자(H_legit)의 트래픽은 S2 기본 경로에서 S3 우회 경로로 옮겨진다. 이 전환 순간에 정상 패킷이 하나라도 버려지면 안 된다. 목표는 **정상 패킷 손실 0%**이다.

## 2. 측정 방법

1. 다이아몬드 토폴로지와 Ryu 컨트롤러를 실행하고 `pingall`로 기본 경로(S1 → S2 → S4)를 설치한다.
2. **기준선**: H_legit → H_server로 10ms 간격 ping 1,000개를 보낸다. 경로 전환은 없다.
3. **측정**: 같은 ping을 다시 보내고, 시작 3초 뒤에 우회 규칙(Priority 100)을 주입한다.
4. ping 손실률과 우회 규칙의 `n_packets`로 무유실과 실제 경로 전환 여부를 함께 확인한다.

### 우회 규칙과 설치 순서

| 순서 | 스위치 | 규칙 | 의미 |
|:---:|:---:|:---|:---|
| 1 | S3 | `nw_dst=10.0.0.4 → port 2` | S3에서 서버 방향(S4)으로 |
| 2 | S3 | `nw_dst=10.0.0.1 → port 1` | S3에서 복귀 방향(S1)으로 |
| 3 | S4 | `nw_dst=10.0.0.1 → port 3` | 복귀 트래픽도 S3로 |
| 4 | **S1** | `nw_dst=10.0.0.4 → port 4` | **마지막에** 입구를 S3 쪽으로 전환 |

입구 스위치 S1을 가장 나중에 바꾼다. S1이 길을 바꾸는 순간 S3·S4에는 이미 규칙이 있으므로 전환 직후 첫 패킷부터 끊기지 않는다(make-before-break, 계획서의 "선제적 OFPFC_ADD" 원칙).

> 컨트롤러의 REROUTE 명령은 10주차 Tech Lead 구현 예정이다. 이번 측정은 그 명령이 설치할 규칙과 같은 규칙을 `ovs-ofctl`로 직접 주입해 경로 전환을 재현했다.

환경: Mininet 2.3, Open vSwitch(유저스페이스 데이터패스), Ryu 4.34, ping 1,000개 × 10ms 간격.

## 4. 관제탑 UI 검수 (청색 우회 경로 하이라이트)

| 검수 항목 | 결과 |
|:---|:---|
| MITIGATED 단계 상단 스트립 | 청색으로 전환, "S1:2 격리 · 정상 트래픽 S1 → S3 → S4 우회" 표시 |
| 대응 시간 표시 | 탐지→격리, 탐지→우회 시간을 ms 단위로 표시 |
| 토폴로지 우회 링크 | S1–S3, S3–S4 링크가 굵은 청색 + 발광 효과로 강조 |
| 차단 링크 | H_attacker–S1 링크가 회색 점선으로 표시 |
| 복구 후 | NORMAL 복귀 시 스트립이 "정상 · 감지된 위협 없음"으로 돌아옴 |

더미 데이터에서는 탐지→격리 시간이 약 6,000ms로 나온다. 이는 시나리오상 공격 단계를 6초로 둔 재생 설정값이며, 실제 반응 시간(목표 ≤ 100ms)은 컨트롤러 연동 후 12주차 지연시간 측정에서 확인한다.

## 5. 한계와 후속 검증

- 컨트롤러가 REROUTE 명령으로 같은 규칙을 설치하게 되면, 규칙 주입 단계만 컨트롤러 명령으로 바꿔 같은 측정을 반복한다. 기대 결과는 동일하게 손실 0%이다.
- 공격 트래픽이 동시에 들어오는 상황(9주차 In_port 차단 + 10주차 우회 동시 동작)에서의 정상 트래픽 손실은 14주차 종합 시나리오에서 측정한다(목표 ≤ 2%).
- 유저스페이스 OVS에서 측정했다. 경로 전환의 무유실 여부는 데이터패스 종류와 무관하지만, 지연시간 수치는 커널 데이터패스에서 다를 수 있다.
