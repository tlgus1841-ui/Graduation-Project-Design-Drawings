# [설계안] SDN 동적 망분리 (Dynamic Network Segmentation)

> 상태: 검토중 (작성 김관우, 컨트롤러 담당 박시현 검토 필요)
> 한 줄 요약: **평소엔 망을 나눠서 막고, 넘으려는 시도를 보고, 의심 PC는 격리망으로 보낸다.**

---

## 1. 왜 하는가

| 지금의 한계 | 망분리로 바뀌는 것 |
|---|---|
| 모든 호스트가 서로 통신할 수 있다 (컨트롤러는 목적지 IP만 보고 전달) | 허용한 통신만 통과한다 (기본 차단) |
| 랜섬웨어가 **열린** 파일 공유(445)로 퍼지면 실패 응답이 안 생겨 못 잡는다 | 사용자 PC끼리의 445 · 3389가 막혀 퍼질 길이 없고, 막힌 시도 자체가 탐지 신호가 된다 |
| 위험 단계 대응이 포트 통째 차단이라, 한 포트 아래 정상 사용자와 공격자가 섞이면 정상 사용자도 끊긴다 | 의심 PC 하나(MAC · IP)만 격리망으로 옮긴다 |
| 방화벽 규칙(ACL)만 걸면 "원래 있는 기능"이 된다 | 탐지 결과에 따라 망이 바뀌는 **동적** 망분리로 차별화한다 |

배경: 공공기관 망분리는 국가정보원의 국가 망 보안체계(N²SF)로 개선되는 중이다. 업무 중요도에 따라 기밀(C) · 민감(S) · 공개(O)
등급을 나누고 등급별로 통제를 다르게 둔다. 물리적으로 망을 나누던 것을 등급별 논리적 통제로 바꾸는 흐름이라, SDN 정책 기반 망분리와 방향이 같다.
(시행 시점 등 세부 사항은 발표 전에 국가정보원 · 국가사이버안보센터 공지로 다시 확인할 것)

## 2. 망 구분 (Zone)

| 망 | 들어가는 호스트 (예시) | 설명 |
|---|---|---|
| 사용자망 `USER` | H_legit, H_attacker, 내부 사용자 PC | 일반 업무 PC. 공격자도 처음엔 여기 있는 평범한 PC다 |
| 서버망 `SERVER` | H_server (웹 80, DNS 53) | 보호 대상 서비스 |
| 관리망 `ADMIN` | 관제탑 · 업데이트 서버 (확장 구조에서 추가) | 관리자만 접속. 격리된 PC가 연결할 수 있는 유일한 곳 |
| 격리망 `QUARANTINE` | (평소 비어 있음) | 의심 PC를 옮겨 두는 곳. 관리망의 정해진 서비스만 가능 |

망은 **IP 주소 대역이 아니라 컨트롤러 정책**으로 나눈다 (논리적 망분리). 지금 테스트베드는 10.0.0.0/24 하나라서
대역을 나누려면 라우팅부터 바꿔야 하는데, 정책 방식은 그대로 둘 수 있다.

## 3. 허용 통신 표 (기본은 차단)

| 출발 → 도착 | 허용 | 비고 |
|---|---|---|
| USER → SERVER | TCP 80, UDP 53, ICMP echo | 지금 정상 사용자 트래픽 (`traffic/normal_user.py`) |
| SERVER → USER | 위 연결의 응답 | 서버 쪽 입구에서 출발 포트(80 · 53)로 구분 (아래 4.3) |
| USER → USER | **없음** (445 · 3389 · 135 · 139 모두 차단) | 랜섬웨어 · 웜 확산 경로 |
| USER → ADMIN | 없음 | 관리망은 관리자 PC만 |
| ADMIN → 모든 망 | 전부 | 관리 · 점검 |
| QUARANTINE → ADMIN | 업데이트 서버 TCP 443, DNS 53 | 치료 · 점검용 |
| QUARANTINE → 그 외 | **없음** | 서버망 접근도 차단 |
| 컨트롤러 확인 ping 10.0.0.250 ↔ SERVER | 항상 | 서비스 상태 확인 (위험 단계 판단에 씀) |

정책은 코드가 아니라 설정 파일로 둔다 (지금 다이아몬드 구조가 코드에 고정돼 생긴 문제를 반복하지 않기 위해):

```yaml
# config/zones.yaml (예시)
zones:
  USER:   [10.0.0.1, 10.0.0.2]
  SERVER: [10.0.0.4]
  ADMIN:  []
allow:
  - {from: USER, to: SERVER, proto: tcp, dst_port: 80}
  - {from: USER, to: SERVER, proto: udp, dst_port: 53}
  - {from: USER, to: SERVER, proto: icmp}
  - {from: QUARANTINE, to: ADMIN, proto: tcp, dst_port: 443}
  - {from: QUARANTINE, to: ADMIN, proto: udp, dst_port: 53}
always_allow: [10.0.0.250]   # 서비스 상태 확인 ping
```

## 4. 스위치 규칙 설계 (OpenFlow 1.3)

### 4.1 테이블 구조

지금: `0 세기 → 1 속도 제한(경고) → 2 전달`

바꾼 뒤: `0 세기 → 1 망 정책 → 2 속도 제한 → 3 전달`

| 테이블 | 하는 일 | 왜 이 순서인가 |
|---|---|---|
| 0 세기 | 지금 그대로 (SYN · UDP · ICMP · 실패 응답) | 막히는 패킷도 **먼저 세야** 공격 판단에 쓸 수 있다 |
| 1 망 정책 (새로) | 허용 목록에 맞으면 다음 테이블, 아니면 버림 + 셈 | 속도 제한 규칙(우선순위 100, in_port 일치)과 같은 테이블에 두면, 한 패킷은 한 규칙에만 걸려 망 정책을 건너뛴다 |
| 2 속도 제한 | 지금 1번 테이블 그대로 | — |
| 3 전달 | 지금 2번 테이블 그대로 | — |

### 4.2 어디에 거는가

정책은 **출발 호스트가 붙은 입구 스위치에만** 건다 (예: H_attacker면 S1). 중간 스위치는 지금처럼 전달만 한다.
패킷이 망을 넘기 전에 입구에서 버려지므로 중간 링크 · 서버가 공격 트래픽을 받지 않는다.

### 4.3 규칙 예시 (H_attacker, 입구 S1 포트 2)

| 우선순위 | 일치 조건 | 동작 |
|---|---|---|
| 300 | `eth_src=공격자 MAC, ipv4_dst=10.0.0.4, tcp, tcp_dst=80` | 다음 테이블 |
| 300 | `eth_src=공격자 MAC, ipv4_dst=10.0.0.4, udp, udp_dst=53` | 다음 테이블 |
| 300 | `eth_src=공격자 MAC, ipv4_dst=10.0.0.4, icmp` | 다음 테이블 |
| 10 | `in_port=2, ipv4` (나머지 전부) | **버림** + 망 넘기 시도로 셈 (cookie 태그) |
| 5 | `arp` | 다음 테이블 (Proxy ARP는 지금처럼 컨트롤러가 답함) |

서버의 응답은 서버가 붙은 입구(S4 포트 1)에서 허용한다 (SERVER → USER):

| 우선순위 | 일치 조건 | 동작 |
|---|---|---|
| 300 | `eth_src=서버 MAC, tcp, tcp_src=80` / `udp, udp_src=53` / `icmp` | 다음 테이블 |
| 300 | `eth_src=서버 MAC, ipv4_dst=10.0.0.250` | 다음 테이블 (확인 ping 응답) |
| 10 | `in_port=1, ipv4` (나머지 전부) | 버림 + 셈 (서버가 먼저 사용자에게 연결을 거는 일은 없어야 한다) |

- 일치 조건에 `in_port`가 아니라 **`eth_src`(MAC)**를 쓴다. 그래야 한 포트 아래 여러 PC가 있어도 PC마다 다른 망에 둘 수 있다.
- Proxy ARP는 망이 달라도 답한다. ARP를 막으면 "없는 주소"로 세져 내부 확산 규칙과 섞이기 때문이다. 실제 차단은 IP 패킷에서 한다.

### 4.4 넘으려는 시도 세기 → 탐지 신호

- 버리는 규칙(우선순위 10)에 지금 세는 규칙과 같은 방식의 cookie를 붙이고, 컨트롤러가 1초마다 1번 테이블 통계도 함께 요청한다.
- 새 카운트 종류: `CountKind.ZONE_DENY = "zone_deny"` (이 PC가 망을 넘으려다 막힌 패킷 수).
- 판단 엔진(`model/criteria_engine.py`)에 규칙 하나 추가:
  - **망 넘기 시도**: 짧은 창(4초)에 막힌 시도 N개 이상이면 내부 확산 후보. N은 지금 기준과 같은 방식(정상 측정 최댓값 × 2)으로 정한다.
  - 정상 사용자는 허용 목록 밖으로 나갈 일이 없으므로 정상 측정값은 0에 가까울 것으로 예상된다 (측정으로 확인).
- 이렇게 하면 "열린 PC로 퍼지는 랜섬웨어"가 **막히면서 동시에 탐지**된다. 막힌 시도는 접속 성공이 아니므로 지금 규칙으로는 안 보이던 것이다.

## 5. 격리망으로 옮기기 (동적 대응)

### 5.1 대응 단계 (지금 단계에 끼워 넣기)

| 단계 | 지금 | 바뀐 뒤 |
|---|---|---|
| 주의 WATCH | 지켜보기 | 그대로 |
| 경고 WARNING | 그 종류 패킷만 초당 50개 | 그대로 (Flood 같은 양 공격은 속도 제한이 맞다) |
| 위험 DANGER | 포트 통째 격리 + 우회 | **내부 확산 · 스캔 · 망 넘기 시도**: 그 PC만 격리망으로 이동<br>**Flood**: 지금처럼 포트 격리 + 우회 (양이 많으면 입구에서 끊는 게 맞다) |

### 5.2 옮기는 방법

1. AI Worker가 위험 경보를 낸다 (지금 `sdn:anomaly:alert` 그대로).
2. 컨트롤러가 그 PC의 망 정책 규칙(4.3의 우선순위 300)을 지우고, QUARANTINE 허용 목록으로 다시 깐다.
3. 관제탑에 "격리망 이동: 10.0.0.2 (사유: 내부 확산)"을 띄운다.
4. **복귀는 관리자만**: 관제탑에서 확인 후 "원래 망으로 복귀" (지금 재학습 승인처럼 사유를 남김).
   자동 복귀는 하지 않는다. 감염 PC가 조용해졌다고 치료된 것은 아니기 때문이다.

### 5.3 계약(스키마) 추가 — 하위 호환 유지

| 항목 | 추가 |
|---|---|
| `DefenseAction` | `QUARANTINE`, `RELEASE` |
| `ControlCommandMessage` | `target_ip: Optional[str]` (MAC · IP로 옮길 PC 지정, 없으면 기존처럼 포트 기준) |
| `CountKind` | `ZONE_DENY` |
| API | `POST /api/control/quarantine/release` (사유 필수, 지금 수동 제어 API와 같은 검증) |

## 6. 꼭 지켜야 할 예외 (안전장치)

| 예외 | 이유 |
|---|---|
| 컨트롤러 확인 ping(10.0.0.250, 가상 MAC 00:00:00:00:00:fa) | 막히면 서비스 악화로 잘못 판단해 위험 단계가 잘못 난다 |
| 스위치 사이 트렁크 포트 | 망 정책은 입구(접속 포트)에만 건다. `harness/safety/whitelist_guard.py`의 트렁크 보호 그대로 |
| 보호 서버(H_server) | 서버는 격리망으로 옮기지 않는다 (화이트리스트) |
| 관리망 | 관리자 PC가 격리되면 복귀 버튼을 누를 사람이 없다. 관리망 PC는 격리 대상에서 뺀다 |

## 8. 검증 계획

새 공격 도구는 만들지 않는다. 기존 `traffic/*.py`만 쓴다.

| 실험 | 확인할 것 | 합격 기준 |
|---|---|---|
| 정상 10분 (접속 몰림 포함) | 정상 사용자가 막히지 않는가, zone_deny 평소값 | 정상 사용자 손실 지금과 같음, 경보 0회 |
| 내부 확산 (`traffic_spread.py`, 대상에 445를 연 가상 PC 포함) | 막히는가, 탐지되는가, 격리망으로 옮겨지는가 | 대상 PC에 접속 0건, 위험 → 격리망 이동, 이동 뒤 서버 접속 불가 · 관리망만 가능 |
| 포트 스캔 (`traffic_scan.py`) | 지금처럼 탐지 + 격리망 이동 | 탐지 시간 지금 수준 유지 |
| Flood (UDP · ICMP · SYN) | 지금 대응(포트 격리 + 우회)이 그대로인가 | 탐지 시간 · 정상 손실 지금 수준 유지 |
| 관리자 복귀 | 복귀 뒤 원래 허용 목록이 다시 적용되는가 | 서버 접속 정상 |
| 같은 포트 아래 정상 + 공격자 (확장 구조) | 공격자만 격리망으로 가는가 | 같은 포트의 정상 사용자 손실 없음 |

## 9. 같이 정할 것 (박시현 검토)

1. **스위치 확장 · 6-A(Mininet 없이 OVS만으로 구동)와 순서**: 망 정책은 입구 스위치 기준이라 구조가 바뀌면 규칙 위치도 바뀐다.
   구조(스위치 8~10개, 가상 PC 20대 정도)를 먼저 정하고 그 위에 올리는 것을 제안.
2. **테이블 번호를 미는 것**: 기존 테스트 · 측정 도구가 테이블 번호를 쓰므로 한 번에 바꿔야 한다.
3. **격리망 복귀 권한**: 관제탑 수동 제어와 같은 사람(관리자)으로 할지.
4. **관리망 · 업데이트 서버 호스트 추가**: 확장 토폴로지에 넣을지.
