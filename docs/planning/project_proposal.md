## 2. 개발 배경 및 필요성

### 2.1 기존 하드웨어 네트워크 인프라의 한계
1. **중앙 집중식 가시성 부재:** 레거시 네트워크 스위치와 라우터는 개별 장비 단위의 분산 제어로 동작하여 네트워크 전역의 트래픽 흐름을 실시간으로 한눈에 파악하기 어렵고, 장애나 공격 발생 시 장비별 CLI 수동 점검에 의존함.
2. **수동 대응 병목(Human-in-the-loop Bottleneck):** DDoS 공격이나 비정상 트래픽 폭주 발생 시 엔지니어가 수동으로 ACL을 등록하고 라우팅 경로를 재설정하는 데 수 분~수십 분이 소요되어 무중단 서비스 연속성(BCP)이 침해됨.
3. **IP 스푸핑(변조) 대응의 구조적 결함:** 발신지 IP(Src IP)를 무작위로 위조하는 현대 DDoS 공격에 대해 전통적인 IP 차단 룰을 적용하면 라우터/스위치의 플로우 테이블 메모리가 고갈(Flow Table Overflow)되어 장비 전체가 마비됨.

### 2.2 SDN과 경량 AI를 결합한 자가 방어(Self-Defending)의 당위성
* **소프트웨어 정의 네트워킹(SDN):** 제어 평면(Control Plane)과 데이터 평면(Data Plane)을 물리적으로 분리하여, 중앙 컨트롤러가 소프트웨어 코드로 네트워크 경로를 밀리초(ms) 단위로 프로그래밍 가능.
* **자가 치유(Self-Healing) 자동화:** 중앙 컨트롤러에 경량 머신러닝 이상 탐지 엔진을 결합하여 사람의 개입 없이 **[이상 탐지 ➔ 물리/가상 인그레스 포트(`in_port`) 즉각 격리 ➔ 정상 트래픽 다중 경로 우회(Rerouting) ➔ 공격 소멸 후 자동 복원]** 라이프사이클을 완성함.

## 3. 시스템 핵심 목표 및 차별성

| 핵심 목표 | 세부 구현 내용 | 기존 방식 대비 차별성 |
|:---|:---|:---|
| **1. 경량 2-Tier 모니터링** | 1차: 주기적 포트 대역폭 폴링(2초)<br>2차: 임계 초과 시 In_port/세부 플로우 정밀 분석 | 컨트롤러 부하(CPU/메모리)를 90% 이상 절감하면서 정밀 분석 수행 |
| **2. In_port 기반 스푸핑 방어** | 출발지 IP 매칭 대신 유입 물리/가상 포트(`in_port`) 기반 `Priority 100 Drop` 규칙 주입 | 공격자가 IP를 수만 번 변조해도 플로우 테이블 폭발 없이 1개 룰로 원천 차단 |
| **3. Dijkstra 무유실 자율 우회** | 공격 피해 링크 경유 정상 플로우를 대체 경로로 `OFPFC_MODIFY` 실시간 스위칭 | 패킷 드롭 및 서비스 단절 없는 동적 다중 홉 Failover |
| **4. FSM 라이프사이클 자가 복구** | Drop 룰(15초)과 우회 룰(10초)의 타임아웃 차등 제어로 공격 종료 후 기본 최단 경로 복원 | 관리자의 수동 롤백 작업 불필요, 자율 복구 보장 |
| **5. 실시간 웹 관제탑 시각화** | React + vis-network 인터랙티브 토폴로지 맵 & WebSocket 기반 실시간 트래픽/경보 관제 | CLI 디버깅 탈피, 시연성 및 시스템 상태 가시성 극대화 |

## 5. 세부 기능 명세

### 5.1 데이터 평면 (Data Plane)
* **다이아몬드 토폴로지 구성:** Core 스위치와 Aggregation/Edge 스위치 간 2개 이상의 독립된 경로를 구성하여 장애/공격 시 우회 경로를 물리적으로 확보.
* **단독 액세스 포트 분리:** 공격 단말(H_att)과 정상 단말(H_legit)을 개별 스위치 포트에 1:1로 격리 매핑하여, 공격 포트 차단 시 정상 단말의 통신 권한을 보호.
* **모의 트래픽 주입 (Scapy):**
  - 정상 트래픽: 정상 IP 간 일정한 간격의 HTTP/TCP/ICMP 트래픽 생성.
  - 공격 트래픽: 발신지 IP를 무작위 변조한 대규모 SYN Flooding 공격 주입.

### 5.2 제어 평면 (Control Plane)
* **L2/L3 스위칭 & 루프 방지:** LLDP 패킷 기반 링크 탐색 및 NetworkX 그래프를 활용한 패킷 루프 없는 최적 경로 산출.
* **2-Tier 텔레메트리 파이프라인:** 
  - 1차: 전체 스위치 포트 통계를 2초 주기로 수집하여 대역폭 급증 감지.
  - 2차: 임계치를 초과한 특정 포트에 대해서만 세부 플로우/인그레스 통계를 집중 질의.
* **동적 플로우 프로그래밍:** 기존 플로우 엔트리를 삭제하지 않고 `OFPFC_MODIFY`를 통해 Action Output 포트만 대체 링크로 갱신하여 패킷 유실 방지.

### 5.3 AI 이상 탐지 워커 (AI Worker)
* **이벤트 기반 독립 프로세스:** Ryu의 Eventlet 이벤트 루프 블로킹을 방지하기 위해 별도 Python 프로세스로 분리.
* **5대 표준 SDN 파생 피처 계산:**
  $$\Delta \text{PPS} = \frac{\Delta \text{Packet\_Count}}{\Delta t}, \quad \Delta \text{BPS} = \frac{\Delta \text{Byte\_Count}}{\Delta t}, \quad \text{BPP} = \frac{\Delta \text{Byte}}{\Delta \text{Packet}}$$
  포트 유입 패킷 비율 및 세션 급증도를 종합하여 비지도 머신러닝(Isolation Forest) 모델로 실시간 이상치 스코어 산출.

### 5.4 웹 관제탑 (Web Control Tower)
* **실시간 대시보드:** WebSocket 연결을 통해 수신되는 토폴로지 노드/링크 상태를 vis-network 인터랙티브 그래프로 렌더링.
* **보안 이벤트 타임라인:** 공격 탐지, In_port 차단 룰 주입, 우회 라우팅 활성화, 타임아웃 자가 복구 전 과정을 실시간 로그 타임라인으로 표시.
* **수동 비상 제어(Emergency Override):** 관리자가 특정 포트나 호스트를 웹 대시보드에서 즉각 격리/복원할 수 있는 REST API 제어 패널 제공.

## 6. 핵심 알고리즘 및 방어 메커니즘

### 6.1 In_port 격리 기반 IP 스푸핑 무력화
```
[공격 패킷 유입] ───> OVS Switch (Port 1: H_attacker)
                        │
                        ▼ (Source IP: 무작위 변조, In_port: 1)
                  Ryu Controller
                        │
                        ▼ [AI Anomaly Detection: Anomaly Score > Threshold]
                  Action: In_port 기반 차단 룰 주입
                        ├── Match: in_port=1 (IP 매칭 사용 안 함)
                        ├── Action: Drop
                        ├── Priority: 100 (최우선순위)
                        └── Idle_Timeout: 15초
```

### 6.2 다중 경로 Dijkstra 우회 및 안전 복구 FSM (Finite State Machine)
* **정상 상태 (Normal):** 최단 경로 $S_1 \rightarrow S_2 \rightarrow S_4$로 통신.
* **공격 감지 상태 (Attacked):**
  - 공격 유입 포트 `in_port=1` Drop 룰 적용.
  - $S_2$ 경유 트래픽을 대체 경로 $S_1 \rightarrow S_3 \rightarrow S_4$로 `OFPFC_MODIFY` 우회 라우팅 (`Idle_Timeout = 10초`).
* **자가 복원 상태 (Self-Healing):**
  - 공격이 중단되면 `우회 룰 타임아웃(10초)`이 먼저 만료되고, 뒤이어 `차단 룰 타임아웃(15초)`이 해제되면서 원래 기본 최단 경로로 무유실 자동 복귀.

## 10. 시연 시나리오 및 기대 효과

### 10.1 종합 시연 4단계 시나리오
1. **정상 통신 (Normal Baseline):**
   - H1과 H2가 최단 경로($S_1 \rightarrow S_2 \rightarrow S_4$)를 통해 정상 HTTP/Ping 트래픽 통신.
   - 웹 관제탑에서 초록색 링크 및 정상 PPS/BPS 대역폭 시각화 확인.
2. **공격 주입 및 탐지 (Attack & Detection):**
   - 공격자 H_att에서 Scapy를 이용해 타겟 서버로 대규모 Random IP Spoofing SYN Flooding 주입.
   - 1차 포트 혼잡 감지 ➔ 2차 정밀 분석 ➔ AI Anomaly Score 급증 ➔ 웹 관제탑에 크림슨 레드 경보 팝업 발생.
3. **자율 방어 및 우회 라우팅 (Defense & Rerouting):**
   - 공격 유입 포트(`in_port`)에 `Priority 100 Drop` 플로우 즉각 주입 (공격 트래픽 소멸).
   - 피해 링크를 경유하던 H1-H2 정상 트래픽은 대체 경로($S_1 \rightarrow S_3 \rightarrow S_4$)로 `OFPFC_MODIFY` 무유실 우회 전환.
   - 웹 관제탑 토폴로지 상에서 격리 포트(적색) 및 우회 링크(퍼플/청색)로 상태 전환 실시간 시각화.
4. **무중단 자가 복구 (Self-Healing Recovery):**
   - 모의 공격 스크립트 중단 ➔ Drop 및 우회 룰의 Idle Timeout 만료 ➔ 최단 경로로 자동 롤백 및 정상(초록색) 복귀 확인.

### 10.2 기대 효과 및 학술·기술적 가치
* **기술적 가치:** 기존 상용 침입 탐지 시스템(IDS/IPS)의 한계인 IP 스푸핑 공격에 대해, SDN 포트 단위 격리 기법을 접목하여 저비용·고효율의 완전 자율 방어 체계를 실증함.
* **실무적 가치:** 학부 수준의 단순 CRUD 웹 프로젝트를 탈피하여, OS 커널, 네트워크 프로토콜(OpenFlow), 비동기 분산 IPC(Redis), 인공지능(ML), 최신 프론트엔드가 결합된 고난이도 풀스택 시스템 엔지니어링 역량을 입증함.
