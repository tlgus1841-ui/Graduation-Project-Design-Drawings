# 졸업작품 주제 선정 배경 및 당위성 보고서
## : Self-Defending SDN Tower (SDN 기반 분산 트래픽 이상 탐지 및 자율 라우팅 관제 시스템)

---

## 1. 기획 배경 및 문제 제기 (Background & Problem Statement)

### 1.1 전통적 네트워크 인프라의 구조적 한계
* **하드웨어 종속성 및 정적 라우팅:** 기존 네트워크 스위치와 라우터는 벤더사 전용 CLI와 하드웨어 펌웨어에 의존하여, 급변하는 네트워크 트래픽 상황에 동적으로 적응하지 못함.
* **수동 대응의 지연 (Human-in-the-loop Bottleneck):** DDoS 공격, 비정상 트래픽 폭주 발생 시 네트워크 엔지니어가 수동으로 방화벽 ACL을 등록하거나 라우팅 테이블을 수정해야 하며, 대응하는 수 분~수십 분 동안 서비스 마비(Downtime)가 불가피함.
* **제어와 데이터 평면의 결합:** 분산된 장비마다 개별적으로 정책을 내려야 하므로 전체 토폴로지 차원의 글로벌 최적화 및 즉각적인 우회 경로 설정이 원천적으로 불가능함.

### 1.2 왜 지금 "SDN + 자율 제어(Self-Defending)"인가?
* 제어 평면(Control Plane)과 데이터 평면(Data Plane)을 분리하는 **SDN(Software-Defined Networking)**은 네트워크를 소프트웨어 코드로 직접 프로그래밍할 수 있게 함.
* 중앙 집중식 시야를 확보한 SDN 컨트롤러에 **경량 머신러닝 이상 탐지 엔진**을 결합하면, 사람이 개입하지 않고도 밀리초(ms) 단위로 공격을 인지하고 우회 경로를 프로비저닝하는 **'자율 무중단 네트워크(Autonomous Self-Healing Network)'**를 현실화할 수 있음.

## 3. 왜 '이 주제'여야만 했는가? (5대 핵심 선정 이유)

### ① "감시(Monitoring)"를 넘어선 "자가 치유(Self-Healing)" 폐루프의 완결성
대다수의 네트워크 보안 프로젝트는 침입 탐지(Detection) 및 시각화 단계에서 멈춥니다. 그러나 본 프로젝트는 다음의 5단계 폐루프(Closed-Loop Control)를 완벽하게 자율화합니다:
```
[실시간 메트릭 수집] ➔ [경량 AI 이상 탐지] ➔ [공격 유입 진입 포트 격리] ➔ [Dijkstra 기반 정상 플로우 우회] ➔ [공격 소멸 시 자가 복구]
```
네트워크 장애 및 공격 발생 시 관리자의 수동 개입 없이 인프라 스스로 방어하고 복원하는 **'무중단 인프라 자율화'**라는 최고 난이도의 공학적 목표를 달성합니다.

### ② 컴퓨터공학 전공 4대 역량의 유기적 융합 (Full-Stack Systems Engineering)
학부 과정에서 학습한 컴퓨터공학 핵심 지식이 유기적으로 맞물려 돌아가는 아키텍처를 가집니다:
1. **인프라 & 시스템:** Linux 커널, OVS(Open vSwitch), Docker 컨테이너 격리, 네트워크 네임스페이스
2. **차세대 네트워크:** OpenFlow 1.3 프로토콜 스펙, SDN 컨트롤러(Ryu), LLDP 기반 동적 토폴로지 탐색, Dijkstra 최단 경로 알고리즘
3. **인공지능 & 데이터 엔지니어링:** 실시간 시계열 트래픽 피처 엔지니어링($\Delta \text{PPS}$, $\Delta \text{BPS}$, $\text{BPP}$ 등), 초저지연 머신러닝(Isolation Forest) 비동기 추론
4. **웹 풀스택 & 실시간 분산 처리:** Redis Pub/Sub 고속 IPC 버스, FastAPI 비동기 WebSocket 브로드캐스팅, React 인터랙티브 토폴로지 시각화

### ③ 현실적 보안 위협(IP Spoofing)에 대한 실효성 있는 해법 제시
* **기존의 순진한 접근법:** 공격자 IP(`src_ip`)를 매칭하여 차단 규칙을 설치함.
  * *문제점:* Scapy 등으로 출발지 IP를 무작위로 위조(Random IP Spoofing)하면 컨트롤러의 플로우 테이블이 폭발(Flow Table Exhaustion)하여 스위치가 마비됨.
* **본 프로젝트의 독창적 해결책:** 
  * 변조 가능한 IP 대신 패킷이 실제로 들어오는 물리적 진입 포트인 **인그레스 포트(`in_port`)를 특정하여 차단 규칙 주입**.
  * 스위치 간 상호 연결 포트(Trunk Port)는 보호하고, 공격 단말이 직결된 **액세스 포트(Access Port)만 정밀 격리**하여 정상 단말 간 통신의 연속성을 보장함.
  * 이는 심사위원들에게 **"네트워크 프로토콜과 패킷 처리 구조를 깊이 이해하고 실무적으로 설계했다"**는 강력한 기술적 설득력을 제공함.

### ④ 심사위원과 청중을 압도하는 직관적 시연성 (Live Visual Monitoring Tower)
백엔드/시스템 프로젝트의 고질적인 약점은 "검은 터미널 화면에서 로그 텍스트만 출력되어 성과가 눈에 보이지 않는다"는 점입니다. 본 프로젝트는 실시간 웹 관제탑(Control Tower)을 통해 직관적이고 극적인 시연을 제공합니다:
1. **정상 상태:** vis-network 토폴로지의 모든 링크와 노드가 안정적인 초록색으로 렌더링, 정상 트래픽 차트 표시.
2. **공격 주입:** Scapy로 DDoS 공격 주입 즉시 대상 링크가 **붉은색으로 점멸**하며 실시간 패킷량 급증.
3. **AI 탐지 & 자동 격리:** 실시간 경보 로그 발생과 함께 공격자 진입 포트가 **적색 차단 아이콘**으로 격리됨.
4. **실시간 우회:** 피해 링크를 통과하던 정상 트래픽이 끊김 없이 **파란색/초록색 우회 링크로 갈아타는 모습** 시각화.
5. **무중단 자가 복구:** 모의 공격 종료 시 타임아웃 및 FSM 감지를 통해 원래의 최단 경로로 자동 복귀.

### ⑤ 3인 협업에 최적화된 독립적·병렬적 분업 구조 (Contract-First Architecture)
* 한두 명의 역량에 편중되는 일반적인 팀 프로젝트의 실패 패턴을 방지합니다.
* **Developer A (SDN & Infra):** Mininet, OVS, Ryu 컨트롤러, OpenFlow 동적 라우팅
* **Developer B (AI & Traffic):** Scapy 공격/정상 트래픽 발생기, 피처 엔지니어링, 저지연 머신러닝 추론 파이프라인
* **Developer C (Web & Control Tower):** FastAPI 비동기 백엔드, Redis 연동, React 토폴로지 및 실시간 차트 대시보드
* 공통 인터페이스(Redis Channel 규격, WebSocket JSON Schema, REST API)를 사전에 확정하여 3인이 병목 없이 100% 병렬로 개발할 수 있는 실무급 협업 체계를 구현합니다.

## 5. 발표 및 심사 대비 가이드 (Defense & Presentation Guide)

### 5.1 1분 엘리베이터 피치 (Elevator Pitch)
> "기존 네트워크 관제는 공격 발생 시 사람이 개입해 방화벽 규칙을 입력할 때까지 서비스가 마비되는 수동적 감시의 한계가 있었습니다. 
> 저희가 개발한 **Self-Defending SDN Tower**는 소프트웨어 정의 네트워킹(SDN)과 경량 머신러닝을 결합하여, **이상 트래픽 감지부터 IP 스푸핑 공격 포트 격리, 정상 트래픽 동적 우회, 공격 종료 후 자가 복구까지 전 과정을 사람 없이 1초 내에 자율 수행하는 무중단 네트워크 관제탑**입니다. 
> 단순한 웹 서비스나 모델 API 래핑을 탈피하여, 시스템 인프라·네트워크 프로토콜·AI 파이프라인·웹 풀스택 기술이 융합된 실무형 시스템 엔지니어링 역량을 증명하기 위해 이 주제를 선택했습니다."

### 5.2 심사위원 예상 질의응답 (Anticipated Q&A)

**Q1. 기존 상용 IDS/IPS나 방화벽과 무엇이 다른가요?**
* **A:** 기존 IDS/IPS는 사전에 정의된 시그니처 룰(정적 패턴) 매칭 위주이며, 인라인(In-line) 장비 병목을 유발합니다. 또한 트래픽 폭주 시 인프라 전체의 라우팅 경로를 글로벌 관점에서 유연하게 재구성하지 못합니다. 본 시스템은 SDN의 중앙 집중식 제어력을 활용해 네트워크 전체 토폴로지 수준에서 최적 우회 경로를 계산하고, 변조된 IP가 아닌 유입 포트 레벨에서 정밀 격리하는 **글로벌 자율 제어 시스템**이라는 점에서 차별화됩니다.

**Q2. 왜 딥러닝(CNN, LSTM 등)이 아니라 머신러닝(Isolation Forest)을 사용했나요?**
* **A:** 네트워크 패킷 처리는 **밀리초(ms) 단위의 지연시간(Latency)**이 생명입니다. 무거운 딥러닝 모델은 GPU 의존성이 높고 추론 지연으로 인해 네트워크 실시간 제어 타이밍을 놓칠 수 있습니다. 비지도 학습 기반의 경량 Isolation Forest는 CPU 환경에서도 수 밀리초 내에 이상치를 스코어링할 수 있어, 컨트롤러의 반응성을 극대화하는 데 가장 적합한 실무적 선택이었습니다.

**Q3. Ryu 컨트롤러와 AI, 웹 서버를 왜 굳이 별도 프로세스로 분리했나요?**
* **A:** Ryu는 `eventlet` 코루틴 기반으로 동작하므로 무거운 연산(AI 추론이나 웹소켓 I/O)이 이벤트 루프를 블로킹하면 스위치와의 OpenFlow Keepalive 통신이 끊어지는 구조적 한계가 있습니다. 따라서 각 컴포넌트를 독립 프로세스로 분리하고 초고속 인메모리 버스인 Redis Pub/Sub으로 비동기 연동하여 **단일 장애점(SPOF)과 블로킹을 원천 차단한 마이크로서비스 아키텍처**를 구축했습니다.
