# 🎯 [실전 라이브 시연 기획서] 독립 웹사이트 서버 연동 및 자율 방어 실증 계획 (2-Server Live Demo Plan)

* **과제명:** Self-Defending SDN Tower (SDN 기반 분산 트래픽 이상 탐지 및 자율 라우팅 관제 시스템)
* **목적:** 가상 시뮬레이션을 넘어, **독립된 실제 웹사이트 서버(Server 1)**와 **SDN 자율 관제 서버(Server 2)**를 연동하여 심사위원 앞에서 웹 서비스 무단절 방어를 실시간으로 증명.
* **작성자:** 박시현 (Tech Lead)
* **상태:** 기획 및 검토 단계 (실행 대기)

## 1. 🏗️ 2-Server 하드웨어 & 네트워크 아키텍처

```
┌────────────────────────────────────────────────────────┐
│ [서버 1: 독립 타깃 웹서버 (Target Web Server)]          │
│ - OS: Ubuntu 22.04 LTS (독립 VM 또는 컨테이너)           │
│ - 서비스: 실제 Nginx 웹사이트 (쇼핑몰/게시판 데모 페이지) │
│ - 서비스 포트: HTTP 80                                  │
│ - IP 주소: 10.0.0.4 / 24                               │
└───────────────────────────┬────────────────────────────┘
                            │
               [GRE 가상 랜선 터널 (L2 통신)]
                            │
┌───────────────────────────┴────────────────────────────┐
│ [서버 2: SDN 관제탑 방어 코어 (SDN Tower & Core)]        │
│ - OS: Ubuntu 22.04 LTS (GCP e2-standard-4 등)           │
│ - Data Plane: Mininet / Open vSwitch (S1, S2, S3, S4)  │
│   * S4의 Port 1: GRE 터널을 통해 [서버 1]과 직결       │
│ - Control Plane: Docker Ryu 4.34 (OpenFlow 1.3)        │
│ - AI Worker: Isolation Forest 이상 탐지 엔진            │
│ - Message Bus: Redis 7.2 Pub/Sub                       │
│ - Web Backend & UI: FastAPI (8000) & React 18 (5173)   │
│ - 모의 트래픽: H_legit (정상 사용자), H_attacker (해커) │
└────────────────────────────────────────────────────────┘
```

## 2. 🎬 4단계 라이브 시연 시나리오 (심사위원 데모 대본)

| 단계 | 시연 화면 1 (진짜 웹사이트) | 시연 화면 2 (관제탑 대시보드) | 내부 시스템 동작 |
|:---:|:---|:---|:---|
| **1단계: 정상** | 브라우저에서 `http://10.0.0.4` 새로고침 시 즉각 로딩 (초록 배너) | S1-S2-S4 기본 경로가 **초록색(ACTIVE)**으로 표시됨 | H_legit의 웹 트래픽이 정상 경로를 통해 서버 1로 무유실 전달 |
| **2단계: 공격** | 웹사이트 새로고침 시 휠이 돌며 렉 발생 (응답 지연) | 관제탑에 **적색 경보(ATTACK)** 점멸, PPS 급증 차트 폭발 | H_attacker가 초당 4,000 PPS SYN Flood 패킷을 서버 1로 주입 |
| **3단계: 방어** | **새로고침을 누르자마자 웹사이트가 다시 0.5초 만에 쌩쌩하게 열림!** | 공격 포트 **회색 점선(BLOCKED)** 차단, 우회로 **청색 발광(REROUTED)** | AI가 78ms 만에 판정 ➔ In_port 2 Drop ➔ S1-S3-S4 우회로 선제 주입 |
| **4단계: 복구** | 웹사이트 무중단 정상 유지 | "자가 복구 완료" 모달 표시 및 링크 **초록색(ACTIVE)** 복귀 | 공격 중단 감지 ➔ FSM 10초 쿨다운 ➔ 차단 룰 자동 삭제 및 기본 경로 롤백 |

## 3. 🛠️ 단계별 준비 및 구축 계획 (4-Step Action Plan)

### [Step 1] 서버 1(타깃 웹서버) 환경 준비
1. 독립 리눅스 환경(독립 VM 또는 독립 Docker 컨테이너) 준비.
2. Nginx 웹서버 설치 및 시연용 데모 HTML 페이지(쇼핑몰/포털 형태) 구성.
3. IP를 `10.0.0.4`로 할당하고 80번 포트 웹 서비스 활성화.

### [Step 2] 서버 1과 서버 2 간 가상 네트워크 케이블(GRE 터널) 연결
1. **서버 1에서:** 서버 2로 향하는 GRE 터널 생성 및 `10.0.0.4` 바인딩.
2. **서버 2에서:** Mininet의 Egress 스위치(`S4`) 1번 포트에 서버 1로 향하는 GRE 터널 연결 (`ovs-vsctl add-port s4 gre0`).
3. **양방향 통신 테스트:** 서버 2의 가상 호스트(`H_legit`)에서 `curl http://10.0.0.4` 실행 시 서버 1의 웹페이지가 수신되는지 확인.

### [Step 3] 토폴로지 파일(`diamond_topo.py`) 외부 포트 모드 옵션 지원
1. `diamond_topo.py`에 `--external-server` 옵션 추가.
2. 옵션 활성화 시 Mininet 내부의 가상 `h_server` 프로세스를 생성하지 않고, 실제 물리/터널 인터페이스(`gre0`)를 S4의 1번 포트로 직접 할당.

### [Step 4] E2E 리허설 및 스트레스 테스트
1. H_attacker로 공격 툴(`traffic_attack.py`)을 쏘았을 때 서버 1의 웹사이트가 실제 부하를 받는지 확인.
2. Ryu 컨트롤러가 차단 및 우회로를 뚫었을 때 서버 1의 웹페이지가 실제로 즉시 살아나는지 검증.
3. 시연 발표용 브라우저 창 2분할(좌: 웹사이트, 우: 관제탑) 레이아웃 배치 최적화.

## 4. 💡 기대 효과 및 차별점

* **"가짜 시뮬레이션"이라는 의구심 100% 해소:** 모의 데이터로 그린 가짜 데모가 아니라, 실제 독립된 웹서버가 공격받고 방어되는 실데이터 기반 라이브 데모임을 증명.
* **시각적 임팩트 극대화:** 심사위원들이 직접 눈으로 웹사이트가 멈췄다가 관제탑이 방어하자마자 다시 열리는 과정을 체감할 수 있어 캡스톤 디자인 및 졸업작품 평가에서 최고점을 확보할 수 있음.
